# DAV file versions

This implementation belongs to CompuMaster.Ocs and is additive. Existing OcsClient download/upload methods and standalone consumers keep their behavior. DavFileVersionClient accepts a caller-owned IWebDavClient, an explicit observed protocol and the DAV root. It provides synchronous wrappers and native asynchronous operations; no general DMS async API is introduced.

| Server | Listing and download | Restoration | Individual removal | Metadata |
| --- | --- | --- | --- | --- |
| Nextcloud | PROPFIND `versions/USER/versions/FILEID/`, GET selected historical child | MOVE selected child to `versions/USER/restore/target` | DELETE selected child, only when authenticated `files.version_deletion` is true; unknown/false rejects locally | DAV timestamp, length, ETag, media type; optional `nc:version-author` and `nc:version-label` |
| ownCloud Classic | PROPFIND `meta/FILEID/v/`, GET selected child | COPY to the current file, conditional on current ETag | Unsupported by this client; no individual DAV removal contract is established | DAV metadata; optional `oc:meta-version-edited-by`, `oc:meta-version-edited-by-name`, `oc:meta-version-tag` |
| ownCloud Infinite Scale | PROPFIND `meta/RESOURCEID/v/`, GET selected historical child; the 8.2 root collection row is `meta/RESOURCEID/` | COPY to the version namespace restores its resource ID; the 8.2 handler does not enforce Destination/If conditions | Unsupported by this client; the 8.2 handler has no individual removal operation | DAV metadata; optional fields remain unknown when absent |
| Generic WebDAV | No built-in version workflow | Unsupported | Unsupported | DeltaV is not implemented |

Authenticated `files.versioning` is separate from protocol recognition, permissions and the presence of retained versions. Callers must establish enabled versioning before presenting this workflow. Missing/disabled namespaces, 401/403 and other errors remain exceptions, never empty history. Only a valid collection with no historical children means empty/pruned history. Nextcloud's synthetic current entry is excluded when its DAV modification time matches the current file, following the official client; its historical GET can otherwise return 404. Unknown modification metadata remains unknown, and version IDs remain opaque. This rule is not applied to ownCloud protocols. Per-file/backend authorization still decides restore/removal; advertised deletion does not prove every storage backend supports it. An administrator's retention/cleanup command is not an individual consumer API.

Listing resolves the stable current file ID from `oc:fileid` (or `oc:id`) and binds versions to that identity and the listing client. Metadata IDs remain distinct from labels/timestamps. Restore and removal revalidate the current file before mutation. COPY additionally requires a strong current ETag and supplies a DAV destination condition. Classic uses this condition to guard concurrent replacement. Infinite Scale 8.2 restores the resource ID in its version namespace and does not enforce this condition: concurrent content updates cannot be guarded atomically. Nextcloud restore targets file identity through its special namespace. Re-list current metadata and history after a mutation; do not assume that restore deletes a historical version or returns a new version ID. A missing/renamed path or changed file ID fails before mutation rather than creating/replacing another file.

`DavFileVersionEndpoint.Resolve` maps a selected personal DAV folder or Infinite Scale space to its version namespace. It preserves the server prefix, selected subfolder and opaque space ID, including folders named `webdav` or `dav/files`. Legacy `/remote.php/webdav` and `/webdav` aliases require the authenticated protocol user ID and resolve to the corresponding personal DAV folder; login/display names are never substituted. Unknown or unsafe paths fail locally. DAV href comparisons normalize percent encoding one segment at a time, including literal versus encoded `$` and `!`; encoded separators, cross-origin resources, unrelated metadata collections, nested versions and duplicate IDs remain rejected.

Download streams the exact listed version to a caller-owned writable stream. No complete-file buffering occurs; active request/copy cancellation is passed through, partial output remains the caller's responsibility, and the response stream is always disposed. Never automatically replay an ambiguous mutation after cancellation/transport failure. Transport ownership and origin/redirect restrictions remain with the caller; untrusted hrefs, cross-origin children, nested/duplicate IDs and foreign-client snapshots are rejected.
